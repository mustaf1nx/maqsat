# MAQSAT — Web-first Life OS

Веб-приложение для личного планирования, задач, целей, идей, работы, финансов, тренировок, привычек и аналитики. **Сначала сайт, затем при необходимости PWA и мобильные приложения на том же API.**

**Статус: рабочий MVP-исходник, а не готовый публичный SaaS.** Backend прошёл базовые тесты; клиентская часть написана на React/TypeScript, но **в этой среде финальная сборка npm не проверена**, так как npm registry был недоступен. Перед реальным запуском проведите сборку, браузерное тестирование и security review.

## Структура

```text
maqsat-web/
├── frontend/            React + TypeScript + Vite, адаптивная тёмная/светлая тема
├── backend/app/         FastAPI, SQLAlchemy, Argon2id, сессии, CSRF
├── backend/migrations/  Alembic-миграция PostgreSQL/SQLite
├── backend/tests/       API-тесты
├── preview/             отдельный HTML-прототип дизайна (без входа/БД)
├── Dockerfile           один Railway-сервис: React static + FastAPI
├── railway.json         конфигурация Railway
└── docs/                видение и архитектура продукта
```

## Что работает в исходниках

- Вход по логину/паролю. Администратор создаёт дополнительные аккаунты в интерфейсе. **Публичной регистрации нет.**
- Данные индивидуальны для каждого пользователя. Администратор видит список аккаунтов, но не имеет API доступа к чужим персональным данным.
- Задачи: создание, выполнение, удаление, приоритеты, сферы, сроки.
- Расписание: недельный календарь с событиями.
- Корзина идей и преобразование идеи в задачу.
- Цели и ручное обновление прогресса.
- Финансы: доходы, расходы, повторяющиеся платежи и их подтверждение (один раз в месяц).
- Работа: проекты, ставки, учёт времени, **ожидаемый**, а не фактически полученный заработок.
- Focus Mode: таймер и сохранение сеанса.
- Здоровье: журнал тренировок (питание, упражнения и сон — следующие этапы).
- Привычки: отметки за день; аналитика и дашборд.
- Изменение пароля, отзыв остальных сессий, светлая/тёмная темы.

**Пока не реализовано:** редактирование всех типов записей, сложные повторяющиеся расписания, напоминания (push/email), автоматическая синхронизация банков, полноценный журнал питания, импорт/экспорт данных, восстановление доступа по email, двухфакторная аутентификация, удаление аккаунта, реальное совместное пространство, backend worker и CI/CD. Безопасность и надёжность требуют дополнительной проверки перед публичным запуском.

## Локальный запуск (Windows PowerShell или macOS/Linux)

Необходимы Python 3.11–3.13, Node.js 20.19+ / 22+, npm.

### 1. Backend

```bash
cd backend
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m alembic upgrade head
python -m app.manage create-admin --username admin --name "Admin"
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

CLI попросит придумать пароль (минимум 10 символов). Пароль **не** включён в исходный код. По умолчанию локально используется SQLite; в Railway подключается PostgreSQL.

### 2. Frontend (в другом терминале)

```bash
cd frontend
npm install
npm run dev
```

Открой `http://localhost:5173`, войди аккаунтом из шага 1. Vite пересылает запросы `/api/*` на локальный FastAPI.

### 3. Backend-тесты

```bash
cd backend
python -m pytest -q
```

## Деплой на Railway

Проект рассчитан на **1 публичный веб-сервис + 1 приватную PostgreSQL базу**.

1. Залей корневую папку `maqsat-web` в GitHub-репозиторий, создай Railway Project и добавь PostgreSQL.
2. Добавь Railway Service из GitHub (root directory `/`, Dockerfile в корне) и создай публичный HTTPS-домен.
3. Добавь переменные веб-сервиса:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (имя сервиса БД может отличаться) |
   | `APP_ENV` | `production` (также задано в Dockerfile) |
   | `APP_SECRET` | секрет из 64+ случайных символов |
   | `APP_ORIGIN` | полный публичный HTTPS URL, например `https://example.up.railway.app` (без `/` на конце) |

   Пример генерации `APP_SECRET` локально: `python -c "import secrets; print(secrets.token_urlsafe(64))"`. Никогда не коммить значение секрета.

4. Запусти деплой. Dockerfile соберёт React и запустит Alembic-миграцию + FastAPI. Проверка доступности: `/healthz`. Dockerfile задаёт `PYTHONPATH=/srv` и запускает миграции через `python -m alembic`, поэтому пакет `app` доступен при миграциях. Если ранее Railway был развёрнут из старого коммита/ZIP, опубликуй обновлённые файлы и запусти **Redeploy**. Проверь, что в настройках сервиса нет старой команды запуска, переопределяющей команду Dockerfile.
5. Создай первого админа **внутри запущенного контейнера Railway**, где доступна приватная сеть PostgreSQL:

   ```bash
   railway ssh -- python -m app.manage create-admin --username admin --name "Admin"
   ```

   Или открой `railway ssh` и выполни команду вручную. Она запросит пароль интерактивно.
6. Войди на сайт и создай остальных пользователей в `Настройки → Создать пользователя`.

Настрой бэкапы PostgreSQL и тестовое восстановление, наблюдаемость, лимиты ресурсов и мониторинг до реального использования конфиденциальных данных. Не храни персональные записи в публичном HTML-прототипе.

## Безопасность (реализованная основа)

- Пароли с Argon2id, cookie с `HttpOnly`, `Secure` в production и `SameSite=Lax`.
- Случайные токены сессий; в БД только их SHA-256 хеши, срок 7 дней; выход отзывает сессию.
- CSRF-токен в заголовке для изменений, проверка `Origin`, запрет cross-site fetch.
- Все персональные API-фильтры используют ID аутентифицированного владельца.
- Деньги — PostgreSQL NUMERIC/Decimal, подтверждение ежемесячного платежа защищено уникальным ограничением.
- Логин с лимитом попыток **в памяти процесса**: это временная мера для одного инстанса, не production-grade distributed rate limiting.
- Контроль доступа к чужим записям и CSRF покрыт базовыми тестами.

## Как позже получить приложение

React-сайт можно превратить в устанавливаемую **PWA**: добавить manifest, иконки, service worker и продумать офлайн-синхронизацию. Если понадобится именно нативное приложение на Android/iOS, можно разработать мобильный клиент, который использует тот же FastAPI, но потребует отдельного мобильного метода авторизации, push-уведомлений, тестирования и публикации. **Не нужно делать приложение сейчас.**
