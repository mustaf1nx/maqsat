# MAQSAT · Calendar Flow · 0.4.0

Бесплатное личное веб-приложение с отдельными аккаунтами: задачи, расписание, идеи, цели, деньги, работа, тренировки, привычки и фокус. Без тарифов и публичной регистрации. Это обновление исходников MAQSAT 0.3, а не отдельный макет. Работающий сайт и его база при подготовке архива не изменялись.

## Главное изменение

**Зажмите левую кнопку мыши на свободном времени календаря, проведите до нужного времени и отпустите.** Во время движения видно выделение и его время. После отпускания появляется небольшая форма: введите название и сохраните. До сохранения в базе нет новой записи. Выделять можно вниз, вверх и между днями. `Esc` отменяет выделение. Простой клик по-прежнему создаёт черновик стандартной длительности.

У готового события можно двигать весь блок, верхнюю границу начала и нижнюю границу окончания. У края сетки включается автопрокрутка. Неудачный серверный запрос не оставляет ложного переноса. Нажатие по событию открывает его детали и действия.

| Возможность | Реализация |
|---|---|

| Сетка | Шаг 5/15/30/60 минут, стандартная длительность, три плотности, начало недели, рабочие часы, второй часовой пояс. |
| Задачи | Задачи со временем на сетке; перенос из списка задач без времени; быстрый выбор «Событие / Задача». |
| Поиск | По загруженному периоду; фильтры календарей и категорий. |
| Корзина | Восстановление целого события/серии, отдельное окончательное удаление. |

| Клавиатура | Создание, переключение видов и периодов, «Сегодня», поиск, справка, клавиатурный курсор времени. |

Это самостоятельный календарь MAQSAT, вдохновлённый привычными взаимодействиями Google Calendar, **не полная копия всех его функций**. Не подключены аккаунты Google, приглашения/RSVP, общий доступ, автоматическое создание Meet, Gmail, бронирование приёмов, праздничные подписки и фоновая доставка push/email. Подробная таблица есть в инструкции календаря.

## Сохранённые разделы MAQSAT

Задачи с чек-листами, сроками и связями; корзина идей с корректной связью на задачу; цели; рабочие проекты и учёт времени; доходы, расходы и подтверждаемые регулярные платежи; таблица тренировок и свои шаблоны; числовые привычки и история; четыре режима фокуса; встроенные и свои шаблоны; аналитика; поиск `Ctrl+K`; светлая/тёмная тема; профиль, смена пароля и экспорт личных записей.

События тренировок продолжают появляться в плане занятий. Изменение времени события обновляет связанный журнал. Удаление события не удаляет уже записанную тренировку. Восстановление события из корзины не привязывает отсоединённые исторические журналы автоматически. Шаблон тренировки не переписывает прошлые занятия.

Регулярные платежи не списываются автоматически и не подключены к банку. Таймер фокуса сохраняется в этом браузере, но не синхронизирует незаконченный сеанс между устройствами. Напоминания проверяются при открытом сайте; закрытая вкладка, сон устройства и ограничения браузера могут помешать доставке.

## Технологии и файлы

```text
frontend/src/features/Calendar.tsx         календарные виды и интеграция
frontend/src/features/calendar/           жесты, формы, детали, настройки
frontend/src/lib/calendarSelection.ts     чистые функции выделения/настроек
backend/app/routers/calendar.py           приватные календарные API
backend/app/recurrence.py                 генератор повторений
backend/app/calendar_transfer.py          ограниченный локальный ICS-обмен
backend/migrations/versions/0003_*        добавочная миграция
backend/tests/                           серверные регрессии
frontend/tests/                          тесты клиентских функций
e2e/                                     сценарии для реальной сборки в CI
qa/                                      результаты выполненных проверок
docs/                                    инструкция, ограничения, QA, источники
```

React + TypeScript + Vite, FastAPI, SQLAlchemy/Alembic. PostgreSQL — основная база Railway; SQLite — локальная разработка/тесты. Новых frontend/backend зависимостей для календаря не добавлено. Архив не содержит фотографий, скриншотов, шрифтовых файлов или чужого runtime. Manrope запрашивается существующим CSS; при недоступности используется системный шрифт.

## Локальный запуск

Нужны Python 3.12, Node.js 22 и npm. Не задавайте production-адрес базы для локальных тестов.

```bash
cd backend
python -m venv .venv
# Git Bash / Windows:
source .venv/Scripts/activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m alembic upgrade head
python -m app.manage create-admin --username admin --name "Administrator"
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Адрес: `http://localhost:5173`. Если `DATABASE_URL` не задана, локально используется SQLite. `.env` автоматически не загружается: задайте переменные в окружении терминала. Пароль администратора вводится интерактивно, не хранится в исходниках.

## Проверки для своей среды

```bash
cd backend
pip install pytest pytest-cov httpx
python -m pytest -q --cov=app --cov-report=term-missing
```

```bash
cd frontend
npm install
npm run typecheck
npm run test:unit
npm run build
```

Из корня проекта после сборки:

```bash
python -m pip install playwright pytest httpx
python -m playwright install chromium
python -m pytest e2e -q
```

`e2e` создаёт одноразовую SQLite и тестовый аккаунт. Снимки экрана не делает. PostgreSQL CI использует отдельную базу `maqsat_test`. Тесты создают и удаляют тестовые таблицы: **никогда не направляйте TEST_DATABASE_URL на рабочую базу**. Файл `.github/workflows/verify.yml` проверяет backend, PostgreSQL и настоящий frontend build + HTTP E2E; наличие файла не означает, что GitHub Actions уже прошёл.

## Безопасность и данные

Пароли хешируются Argon2id; серверные сессии и CSRF/Origin-проверки сохранены. Каждое календарное API ограничивает записи владельцем, включая корзину, импорт и экспорт. Ссылка на встречу ограничена HTTPS; файл ICS не запускает сетевых запросов и не рассылает приглашений. Календарные настройки браузера хранятся отдельно для каждого аккаунта. Финансовые и другие личные модули не открываются другим пользователям или администратору через эти API.

Это не независимый security audit. Лимитер входа остаётся в памяти процесса, и многосерверное ограничение запросов отдельно не реализовано. Внешние резервные копии, мониторинг доступности и реальные мобильные проверки остаются ответственностью развёртывания. Не храните секреты в Git.
