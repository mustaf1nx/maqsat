# Обновление MAQSAT 0.4 Calendar Flow на Railway

База уже работает. **Не создавайте новую PostgreSQL, не удаляйте текущий сервис, volume, аккаунты или существующие переменные.** Эта версия применяет добавочную миграцию `0003_calendar_tools` поверх `0002_daily_flow`. При обновлении с первоначальной версии Alembic последовательно выполнит 0002 и 0003. Не удаляйте прежние миграции и не меняйте alembic_version вручную.

## До обновления

1. Сделайте резервную копию PostgreSQL и убедитесь, что знаете, как восстановить её. Экспорт JSON из приложения не заменяет резервную копию базы.
2. Сохраните текущий коммит рабочего сайта. Надёжнее сначала проверить обновление на отдельном тестовом окружении с копией данных, не на основной базе.
3. Выполните `npm install`, `npm run typecheck`, `npm run test:unit`, `npm run build` в `frontend`; `python -m pytest -q` в `backend`. GitHub Actions также содержит PostgreSQL и браузерный прогон. В среде подготовки полная React19-сборка и PostgreSQL не запускались.

## Файлы

Архив содержит корневую папку `maqsat-web`. Скопируйте **содержимое** этой папки в `~/Desktop/maqsat`, заменив соответствующие исходники. Не вкладывайте весь проект в дополнительную папку внутри репозитория. В корне должны остаться `Dockerfile`, `railway.json`, `frontend/`, `backend/` и `.github/`.

Не удаляйте свою `.git`, локальные секреты или дополнительные личные файлы. `.env` и база не должны попасть в коммит.

## Переменные существующего сервиса

Проект: `loving-generosity`; сервис сайта: **`maqsat`**; окружение: **`production`**; сервис базы: **`Postgres`**.

```text
APP_ENV=production
DATABASE_URL=${{Postgres.DATABASE_URL}}
APP_ORIGIN=https://maqsat.up.railway.app
APP_SECRET=<оставьте существующий секрет>
```

Не публикуйте значение `APP_SECRET` и полный адрес PostgreSQL. `PYTHONPATH=/srv` и `WEB_DIST_DIR=/srv/web_dist` задаются Dockerfile. Веб-порт берётся из `PORT` Railway, его не надо заменять портом PostgreSQL.

## Публикация

Из своей папки репозитория:

```bash
git status
git switch -c maqsat-calendar-flow
git add .
git diff --cached --stat
git commit -m "MAQSAT calendar flow: range selection, calendars and regression tests"
git push -u origin maqsat-calendar-flow
```

Проверьте, что в коммите нет `.env`, реальной базы, выгрузок и секретов. Дождитесь успешных проверок GitHub Actions в этой отдельной ветке. Убедитесь, что production-сервис Railway по-прежнему отслеживает `main`, а не тестовую ветку. После проверки и резервного копирования объедините изменения с `main`. При автодеплое Railway запустит новую версию после обновления отслеживаемой ветки. Если автодеплой выключен, разверните новый коммит через интерфейс сервиса `maqsat`.

Dockerfile сначала собирает frontend, затем при старте запускает:

```text
python -m alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Первого администратора повторно создавать не нужно. Логин и пароль сохраняются в прежней базе.

## Что делает миграция 0003

Добавляет приватные календари, привязку календаря к событию, цвет, признак «весь день», доступность, ссылку на встречу, список напоминаний, отметку удаления в корзину и UID импорта. Существующие события остаются в Основном календаре, сохраняют ID, время, цикл, старое напоминание, исключения, версии и связи с журналами тренировок. Аккаунты и хеши паролей не пересоздаются.

Три миграционных теста на SQLite проверяют старую схему 0001, свежую базу и переход 0002 → 0003 с событиями, исключениями и тренировками. Это не заменяет проверку на копии реального PostgreSQL. Тесты API CI, создающие таблицы с нуля, также не являются проверкой всех вариантов живого обновления.

## Проверка после развёртывания

Откройте новые логи и `/healthz`; войдите существующим аккаунтом. Проверьте старые задачи, финансы, события и тренировки. В календаре выделите пустое время 10:00–11:30, отпустите и сохраните: должна появиться одна запись. Повторите выделение и нажмите Esc: новой записи не должно быть. Перенесите событие, измените границы, откройте детали. Проверьте одно повторение и «Это и последующие», затем корзину и восстановление тестового события. Создайте второй личный календарь и убедитесь, что его скрытие не удаляет данные.

Проверьте отсутствие чужих данных у второго пользователя. Разрешение браузерных уведомлений выдаётся отдельно; закрытая вкладка их не доставляет. Если старый интерфейс остался в открытой вкладке, обновите страницу после успешного деплоя. Не сбрасывайте базу для обновления интерфейса.

## Если нужна смена пароля

Через сайт: **Настройки → Изменить пароль**. Потребуется текущий пароль; другие сессии этого аккаунта завершатся.

Для восстановления доступа владельцем сервера:

```bash
railway ssh -s maqsat -e production
cd /srv
python -m app.manage change-password --username admin
```

Команда просит пароль интерактивно, не сохраняет его в истории команд и завершает все старые сессии пользователя. Не присылайте пароль в чат.

## Откат

Не выполняйте `alembic downgrade` на основной базе без проверенной резервной копии: downgrade удалит поля и таблицы новых функций. Откат исходников не равен откату схемы. Самый предсказуемый путь после неудачной миграции — восстановление проверенной копии вместе с соответствующим коммитом. Подробности миграции и тестов находятся в `QA_REPORT.md`.
